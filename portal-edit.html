Appointment Portal Edit Investigation

This investigation demonstrates my approach to diagnosing an issue affecting appointment editing through a patient portal within a Healthcare Practice Management Platform. The objective was to determine why appointment changes failed for some users, gather technical evidence and provide Engineering with sufficient information to investigate and resolve the behaviour.

Investigation Summary

SystemPatient Appointment Portal
Issue TypePortal Workflow Investigation
SeverityHigh
Customer ImpactPatients could not reliably edit existing appointments.

Background

Customers reported inconsistent behaviour when editing appointments through the online portal. Some changes completed successfully while others failed without a clear error.

As the issue affected patient self-service, a structured investigation was required to isolate the conditions that triggered the behaviour.

Objective

Identify the conditions causing appointment edit failures, produce reliable reproduction steps and document technical evidence for Engineering.

Investigation Timeline

  1. Reviewed customer reports and support history.
  2. Recreated the appointment workflow using test accounts.
  3. Compared successful and unsuccessful edit attempts.
  4. Reviewed browser behaviour and application responses.
  5. Captured screenshots, timestamps and logs.
  6. Documented findings in Jira.
  7. Worked with Engineering to reproduce the issue.
  8. Verified the resolution after deployment.

Investigation

The investigation followed the complete appointment editing journey to determine where expected behaviour diverged from actual system responses.

  • Validated appointment configuration.
  • Tested multiple appointment types.
  • Compared portal responses across different scenarios.
  • Reviewed browser network activity.
  • Established consistent reproduction steps.
  • Provided structured evidence for Engineering.

Evidence Collected

  • Reproduction steps.
  • Screenshots.
  • Browser observations.
  • Configuration comparisons.
  • Customer impact assessment.
  • Technical notes for Engineering.

Root Cause Analysis

The investigation confirmed that appointment editing behaved differently across customer sites despite users following the same workflow. Testing demonstrated that the issue only affected older sites created using a legacy configuration, while newer sites processed appointment availability correctly.

By comparing affected and unaffected sites, I established that the appointment editing workflow was interpreting a legacy null availability value differently. On older sites, the application treated this null value as 0, preventing appointments from being edited even though valid availability existed. Newer sites, which had updated availability records, did not exhibit the same behaviour.

Further testing identified that updating the site's availability forced the legacy records to be refreshed using the current data structure. Once availability had been updated, appointment editing functioned correctly without requiring any further configuration changes. This provided both a reliable workaround for affected customers and valuable evidence for Engineering to investigate the underlying defect.

Providing Engineering with comparisons between legacy and updated sites, repeatable reproduction steps, configuration differences and customer examples enabled them to identify the inconsistency in how legacy availability values were processed. Structured testing also ruled out customer permissions, browser behaviour and appointment configuration as contributing factors.

Confirmed Root Cause

Older customer sites contained legacy availability records where a null value was incorrectly interpreted as 0 during appointment editing. Refreshing the site's availability updated the legacy data structure, providing a successful workaround while Engineering investigated a permanent software fix.
